## 一、阶段目标

本地 RTX 4060 Laptop（8GB 显存）在 3000 条样本 × 1 epoch 的配置下需约 5 小时，且受电源管理中断影响已失败一次。为在有限时间内完成**全量数据训练**，将训练任务迁移至 ModelScope 云端 GPU 实例，本地仅保留推理与界面演示。

**目标产出**：全量数据（19134 条）× 1 epoch 的 LoRA 适配器，回迁本地后与已有基座组合，供 WebUI 演示使用。

## 五、训练结果

| 指标 | 数值 |
|---|---|
| 总步数 | 1,196 步（19,134 ÷ 16） |
| 单步耗时 | 约 11.9 秒 |
| 总时长 | 约 4 小时 |
| 训练状态 | 全程无 OOM，正常结束 |
| 产物 | LoRA 适配器 154.1 MB |

对比本地训练：本地 8GB 卡实测约 **91.6 秒/优化步**（200 条快速训练 1098.7s ÷ 12 步，max_length 768），同规模 1,196 步约需 **30.4 小时**，且受显存与电源中断风险影响已三次失败；云端以 11.9 秒/步 × 1,196 步 ≈ **3.95 小时**完成，并在更长序列（1024）下跑完全量，**加速约 7.7 倍**。

## 六、关键问题与解决

| 问题 | 现象 | 解决方案 |
|---|---|---|
| ms-swift 版本参数漂移 | 网上 v3 教程参数在 4.5.3 全部失效 | 下载 4.5.3 wheel 解包核对源码，逐项校正参数 |
| `--train_type lora` | 未知参数报错 | 改为 `--tuner_type lora` |
| `--tensorboard true` | 4.x 已移除该布尔参数 | 改为 `--report_to tensorboard` |
| `--resume_from_checkpoint auto` | 校验路径存在性，`auto` 直接崩溃 | 脚本自动定位最新 `checkpoint-*` 传真实路径 |
| `modelscope: 未找到命令` | CLI 入口不在 Notebook PATH | 改用 Python API `snapshot_download` 下载数据集 |
| `swift` 命令不可用 | 同上 | 脚本自动探测，缺失时回退 `python -m swift.cli.sft / export` |
| 终端 heredoc 粘贴断裂 | Python 块未执行，报 `import: 未找到命令` | 改为单行 `python -c` 内联执行 |
| peft 版本不兼容 | 云端 peft 0.20 配置含 16 个本地 0.13.2 不识别字段 | 清洗 `adapter_config.json` 多余字段（权重文件不动） |

## 十、后续建议

1. **令牌安全**：训练期间使用的 ModelScope Token 曾在对话中暴露，建议在令牌管理页删除并重建；同时清理云端 `~/.bashrc` 中由 `02_setup_env.sh` 写入的令牌残留。
2. **效果评估**：当前仅验证结构与流畅性，建议引入医学评测基准（如 MedQA 中文子集）量化对比微调前后。
3. **模型发布**：如需「模型已发布」展示点，可在云端或本地执行 `modelscope_migration/05_push_model.sh` 推送合并完整模型。
4. **数据扩展**：可补充多轮问诊对话数据，提升追问与上下文承接能力。
5. **训练证据链固化**：本地目前缺少云端训练输出日志、`trainer_state.json` 与 TensorBoard loss 曲线，建议补入仓库并在 Hub 模型卡写明步数 / 时长 / 超参，使「1,196 步全量完成」可独立举证。
6. **文档口径统一**：`modelscope_migration/云端操作指引.md` 的「约 2 小时」为迁移前预估，应以本文实测「约 4 小时」为准；PPT 第 3 / 10 页占位信息与本文记录人需同步替换。
7. **技术口径分离**：loss mask / 动态 Padding / 早停 / CPU offload 是本地 `train_lora.py`（200 条验证）的实现；云端全量使用 ms-swift 内置流程（BF16 + Flash Attention 2），汇报与简历不要混为一谈。
